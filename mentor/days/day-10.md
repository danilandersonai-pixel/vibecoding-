# День 10 — Рекорды и отчёты

**Цель:** Считать личные рекорды и объём нагрузки и собирать отчёт для тренера

**Результат дня:** Тренер открывает отчёт за месяц по неделям с объёмом, средним и рекордами; определения, пример вручную и правило пустой недели — в docs/report.md, тесты держат пример и пустую неделю, тренер Б чужого не видит — всё в коммитах и на Vercel

## Чек-лист

- [ ] docs/report.md: отчёт описан словами — недели, число тренировок, объём, средний, рекорды; пример — неделя подопечного тренера А, посчитанная вручную: подходы, суммы и итог записаны числами [auto: file]
- [ ] docs/report.md: правило пустой недели — что отчёт показывает вместо среднего; его выбрал автор из двух-трёх вариантов и записал, почему не другие; причина опирается на книгу: пустой ввод — одна из трёх проверок перед «вроде работает», а в пустых списках данные тихо портятся (гл. 3) [auto: file]
- [ ] npm test зелёный, и в нём lib/report.test.ts: неделя из примера docs/report.md — ожидания числами, посчитанными вручную, а не тем же кодом; пустая неделя — по правилу из docs/report.md; тест lib/records.ts — на числах примера; test/report.test.ts: тренер Б не видит в отчёте подопечных тренера А, без входа — ничего [auto: tests]
- [ ] Чужой отчёт: войти тестовым тренером Б (почта и пароль — в .env.test.local), открыть /report?month=<месяц примера из docs/report.md> — ни одного подопечного тренера А; без входа /report ведёт на /login [auto: rls]
- [ ] Отчёт считается в lib/, в выпуске нет новых файлов в supabase/migrations (а если были — каждая прошла в SQL Editor продакшн-проекта раньше git push); после push тренер открывает отчёт на …vercel.app (спросить у автора)

## Вопросы автору

1. Какие числа в lib/report.test.ts вы посчитали вручную и что стало бы с тестом, если бы ожидание считала та же функция?
2. Что ваш отчёт показывает у недели без тренировок, почему вы выбрали это правило и какой тест его держит?
3. Как функция загрузки отчёта узнаёт, кто вошёл, и почему тренер Б не получит подопечных тренера А?

## Практика дня: критерии «готово»

- Отчёт словами в docs/report.md: пример вручную и правило пустой недели — готово, когда: В docs/report.md ваши определения, неделя подопечного, посчитанная вручную, и правило пустой недели с причиной.
- Рекорды в lib/records.ts: из задачи агента или свои — готово, когда: npm test зелёный: рекорды на подходах из вашего примера совпадают с числами, посчитанными вручную.
- Тесты отчёта до кода: пример вручную и пустая неделя — готово, когда: npm test зелёный, а до lib/report.ts был красным; в тесте — числа из docs/report.md, а не вызовы кода отчёта.
- Страница отчёта тренера: данные от имени вошедшего — готово, когда: Вы вошли тренером А: у недели из примера те же числа, что в docs/report.md, у пустой — ваше правило.
- Чужой отчёт: тренер Б не видит подопечных тренера А — готово, когда: npm test зелёный; вы сами вошли тренером Б и открыли отчёт за месяц примера — подопечных тренера А там нет.
- Выпуск отчёта: миграций нет, git push в main — готово, когда: Новых миграций нет; после push тренер на …vercel.app открывает отчёт за месяц со своими подопечными.
- Обновить наставника и проверить день — готово, когда: SKILL.md лежит прямо в .claude/skills/mentor, в days есть файл этого дня, всё в коммите; /mentor 10 проверяет день.
