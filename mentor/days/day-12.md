# День 12 — Приглашение по ссылке

**Цель:** Приглашать подопечного по ссылке и заново проверить безопасность

**Результат дня:** Тренер создаёт и отзывает ссылки-приглашения с одноразовым кодом и сроком; по ссылке подопечный регистрируется через Supabase Auth и попадает к тренеру из записи приглашения; без принятого приглашения пользователь — никто, а второй раз ссылка не работает — это держит тест; выбор о подтверждении почты записан, повторный аудит проведён; миграция попала в продакшн раньше кода, всё в коммитах

## Чек-лист

- [ ] supabase/migrations/…_invites.sql — миграция следующим номером: у таблицы приглашений enable row level security и политики в этом же файле — создаёт, видит, отзывает и удаляет приглашения только тренер (роль — из профиля) и только свои; код длинный и случайный, его ставит база; есть срок, кто принял и отзыв. Проверка кода без входа — функция, которая отвечает только «можно» или «нельзя», без тренера, почты и срока. Тренера подопечному ставит только функция принятия, сам себе ни тренера, ни роли никто не пишет; отвязать подопечного может только его тренер (роль из профиля), сам пользователь и чужие — нет; отвязка снимает тренера, а тренировки и подходы подопечного не удаляет (без каскада). Функция берёт тренера из записи приглашения, привязывает только вошедшего без тренера и роли, отказывает просроченному, использованному и отозванному коду; гасит код и привязывает вместе — проверка «ещё не принят» в том же операторе, что гасит; у обеих функций задан search_path [auto: file]
