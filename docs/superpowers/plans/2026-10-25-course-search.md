# Поиск по курсу, книге и терминам — план

> Запрос автора курса (комментарий на опубликованной странице, у верхней строки главной): «добавить поисковик для нахождения нужного материала, цитаты или термина».
> Приложение: `course/` (Vite 8, React 19, TypeScript, Zod, Vitest + Testing Library, Playwright e2e на порту 4173, oxlint). Вид курса — `docs/superpowers/specs/2026-10-23-course-look-design.md` (переменные `course/src/styles/tokens.css`, общие классы `course/src/styles/base.css`).

## Спецификация

**Что ищем — три источника, три группы результатов в этом порядке:**
1. **«Термины»** — словарь книги `course/content/glossary.json` (280 записей `{ term, definition, refs }`).
2. **«В курсе»** — материалы 21 дня (`getDays()`): тема и цель дня, мысли из книги (`idea`: заголовок и текст), схемы (`diagram`: подпись), ролики (`video`: название), тренажёры, ситуации и помощник ИИ (их заголовки/вопросы), вопросы теста, шаги практики (название и запрос), вопросы наставника. Черновые дни участвуют тем, что в них есть.
3. **«В книге»** — текст книги (`vibe-coding-na-praktike-2026-10.html`, объект `BOOK.blocks`): абзацы, врезки, списки, готовые запросы, таблицы, подписи схем, заголовки разделов. Индекс собирается заранее скриптом в `course/content/book-index.json` и подгружается отдельным куском только при первом открытии поиска.

**Где открывается:** кнопка «Поиск» со значком лупы в верхней строке главной (`SiteBar`, перед «Карта») и в верхней строке шапки дня (`DayHeader`, рядом с «← Карта курса»); с клавиатуры — `/` (если фокус не в поле ввода) и Ctrl+K / ⌘K в любом месте.

**Окно поиска** — `div role="dialog" aria-modal="true" aria-label="Поиск"` поверх страницы с затемнением:
- поле `input type="search"` с подписью «Поиск по курсу и книге» (доступное имя) и подсказкой «Термин, цитата или тема — например, RLS»; фокус в поле при открытии; Esc, «Закрыть» и клик по затемнению закрывают; фокус возвращается на кнопку, которой открыли; Tab не уходит из окна; прокрутка страницы под окном заблокирована;
- до 2 символов — подсказка «Например:» и кнопки-примеры «RLS», «Агент», «спецификация», «коммит» (нажатие подставляет слово);
- от 2 символов — результаты сразу при вводе; над ними строка `aria-live="polite"`: «Найдено: N» (N — всего по трём группам) или «Ничего не нашлось. Попробуйте другое слово или часть слова.»;
- в каждой группе — заголовок `h2` и число, первые 5 результатов и кнопка «Показать все N», если их больше;
- совпадения в названии и фрагменте выделены `<mark>`;
- компьютер (> 640 px): панель 720 px по центру, отступ сверху 10vh, высота до 80vh с прокруткой внутри; телефон (≤ 640 px): на весь экран.

**Совпадение:** запрос и текст нормализуются (нижний регистр, «ё» → «е», кавычки, тире и знаки препинания → пробел, пробелы схлопываются); запрос делится на слова; запись подходит, если каждое слово запроса — подстрока нормализованного текста записи (название + текст). Порядок внутри группы: название совпадает с запросом целиком → название начинается с запроса → все слова в названии → только в тексте; при равенстве — порядок источника (дни по порядку, книга по порядку).

**Фрагмент:** до ~160 знаков вокруг первого совпадения в тексте, с «…» по краям, если текст обрезан; у записи без текста — только название.

**Что делает результат:**
- **термин** — показывает определение целиком; ссылки «В книге» (`book.html#<refs[0]>`, новая вкладка) — если есть `refs`, и «День N» — если термин есть в карточках дня (первый такой день), ведёт к части «Итог дня»;
- **материал курса** — кнопка: окно закрывается, открывается `#/day/N` и страница прокручивается к месту: мысль, схема, тренажёр, ситуация, помощник ИИ — к самому блоку (`id="block-<id блока>"`), ролик — к части «Теория», вопрос теста — к «Проверке понимания», шаг практики — к «Практике», вопрос наставника — к «Наставнику», тема и цель дня — к началу дня. Если этот день уже открыт — просто прокрутка;
- **фрагмент книги** — ссылка `book.html#<ближайший раздел>` в новой вкладке; подпись «Книга · <глава> → <раздел>»; окно остаётся открытым.

**Края:** книга не загрузилась — группа «В книге» говорит «Поиск по книге сейчас недоступен», остальные работают; пока грузится — «Загружаю книгу…». Пустой запрос из пробелов — как пустой. Длинные слова и фрагменты переносятся, на 320 px нет прокрутки вбок. Тёмная тема, видимая рамка фокуса, `prefers-reduced-motion` — без анимации появления.

**Вне рамок:** поиск по субтитрам роликов, нечёткий поиск с опечатками, морфология (кроме подстроки), история запросов.

## Global Constraints

- Цвета, скругления и тени — только переменные из `tokens.css` (`--radius-*`, `--shadow-raised`); нажимаемое ≥ 44 × 44 px; текст ≥ 13 px; контраст текста ≥ 4,5:1 в обеих темах.
- Весь текст интерфейса — по-русски, ровно как в спецификации выше.
- Прокрутка — через `scrollToId` / `scrollBehavior()` из `course/src/home/scroll.ts` (учитывают `prefers-reduced-motion`); переходы между днями — через `navigate()` из `course/src/router.ts`; адрес маршрута `#/day/N` не ломать якорями.
- Индекс книги не входит в основной кусок сборки: только динамический `import()`.
- TDD: тест — красный — код — зелёный. Перед коммитом: `npm test`, `npx tsc -b`, `npm run lint` (в `course/`); у задач с e2e — `npm run e2e` (Playwright уже установлен, никогда не запускать `playwright install`).
- Коммиты с трейлерами `Co-Authored-By` и `Claude-Session` (как в истории репозитория).

## Review Focus

1. Запрос с «ё», заглавными, кавычками «» и дефисом находит то же, что без них («Ёлка» = «елка», «RLS-политика» находит «RLS политика»).
2. Курс открыт на дне 5, результат ведёт в день 5 — страница прокручивается к блоку без перезагрузки; результат ведёт в другой день — день открывается и прокручивается к блоку после отрисовки.
3. Книга не загрузилась (обрыв куска) — «В курсе» и «Термины» работают, в «В книге» — сообщение, без ошибок в консоли.
4. Клавиатура: `/` не открывает поиск, когда фокус в поле заметок или в поле поиска; Esc закрывает и возвращает фокус; Tab не уходит из окна.
5. 320 px: длинный термин и длинный фрагмент книги переносятся, страница и окно не прокручиваются вбок.
