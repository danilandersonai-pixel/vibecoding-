# Теория недели 2 (дни 8–14) — план реализации

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** дни 8–14 становятся готовыми днями курса с короткой теорией, как требует спецификация для недель 2–3. Теория — повторение нужных разделов книги: 2–3 мысли, тренажёр или ситуация, ИИ на странице. К ней добавляются тест, практика для своего приложения, наставник и карточки. В дне 14 — итоговый тест недели 2. Попутно закрываются пять мелочей недели 1.

**Architecture:** содержание дня — данные `course/content/days/day-NN.json`. Механика `weekTest` уже есть (неделя 1), поэтому код меняется только в Задаче 1: тесты отвязываются от черновых дней 8 и 10, проверки целостности становятся строже. Задачи 2–8 — по одному дню. Задача 9 — e2e недели, сборка, публикация.

**Tech Stack:** Vite, React 19, TypeScript, Zod, Vitest, Playwright 1.56.1.

**Spec:** `docs/superpowers/specs/2026-10-21-interactive-course-design.md`, §2 (неделя 2 и «короткие повторения нужных разделов книги с тестом»), §3, §9.

**Факты:**
- `.superpowers/sdd/2026-11-04-book-in-course/week2-theory-research.md` — по дням §3–9, тест недели §10, проект ученика §11, риски §12, правила §13, мелочи недели 1 §14;
- `.superpowers/sdd/2026-11-04-book-in-course/week1-theory-research.md` — схема, проверки, наставник, граф.

**Обязательные правила недели 1:** все разделы «Решения по итогам…» и «Решение для дня 7» в `.superpowers/sdd/2026-11-04-course-theory-week1/day-dispatch-context.md`.

## Global Constraints

- Язык — русский, тон дня 1. Факты — только из книги `vibe-coding-na-praktike-2026-10.html`. Приём курса, которого в книге нет (например «три стопки»), подписывается «В курсе: …».
- Блоки `video` дня остаются первыми и не меняются. `title` и `goal` дня не меняются.
- Короткая теория:
  - **2–3** мысли по 400–700 знаков, у каждой `bookRef` (id `h3`, внутри дня без повтора);
  - повтор раздела из недели 1 допустим, только если строка таблицы задач его называет;
  - схем в дне **не меньше одной**, только из текста книги; `ch8_review` в тексте нет — не брать;
  - **ровно один** тренажёр или одна ситуация — тогда часть «Теория» засчитывается;
  - `ai-helper` с `mode: "ask"` в конце теории.
- `minutes: {theory: 20, practice: 100}`. Тест — 5–7 вопросов, не угадывается. Карточки — 4–8 новых терминов словаря, которых нет в днях 1–7.
- Практика — 4–7 шагов плюс последним шагом «Обновить наставника и проверить день», запрос из `day-02.json` слово в слово. Запросы ≤ 400 знаков, `done` ≤ 120.
- **Миграции:**
  - номер — «следующим номером», имя — с постоянным суффиксом: `<N>_programs.sql`, `<N>_comments.sql`;
  - RLS и политики — в той же миграции;
  - порядок выпуска: проект разработки после «да» → ученик сам вставляет миграцию в SQL Editor проекта продакшна → только потом `git push` в `main`. Push сам выкладывает приложение (s81).
- **Тесты с базой:**
  - supabase-js с публичным ключом и тестовыми пользователями из `.env.test.local`;
  - если тест пишет строки, он создаёт свои в проекте разработки и сам их убирает;
  - секретный ключ не берётся.
- Фоновому агенту — только задачи без базы и миграций. Проверяет он только своим тестом (`npx vitest run <его тест>`), `test/rls.test.ts` без базы не запускает.
- Пароли, строки подключения, ключи — не в чат и не в git. `backups/` — в `.gitignore`.
- Названия мыслей, шагов, вопросов и пунктов не начинаются со слов «Бенчмарки», «Ресторан», «Подписки», «RLS», «Модель» и не повторяют названия дня 1 (§12 исследования, ранги поиска). Если поисковый тест всё же падает — правится тест, а не содержание.
- После дня — `npm run build:graph && npm run build:mentor`. Проверка: `npm test`, `npm run lint`, `npx tsc -b`.
- Коммиты — с двумя строками атрибуции. Ветка `course/theory-days`.

## Review Focus

1. **Миграции и выпуск в продакшн.** Каждая новая таблица — с RLS в той же миграции. В продакшн миграция попадает раньше кода. Ни один шаг не даёт агенту доступ к продакшну.
2. **Негативные проверки чужих данных.** В днях 9–12 нужен второй подопечный тренера Б, его заводит день 11. Тест подтверждает «чужое не видно и не пишется». Тест, который пишет строки, за собой убирает.
3. **Приглашение (день 12).** Код одноразовый и со сроком. Регистрация — через Supabase Auth. Тренер берётся из записи приглашения, а не из адреса. Страница без входа не даёт ничего, кроме формы.
4. **Копии и учения (день 14).** Восстанавливать в проект разработки нельзя. Строка подключения — не в чат. Компромисс «учения на копии разработки» назван честно.
5. **Итоговый тест недели 2.** Каждый вопрос опирается на дни 8–14. Ответы хранятся под ключом `week-2`, отдельно от теста дня 14.
