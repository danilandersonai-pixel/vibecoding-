> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** дни 2–7 курса становятся полными днями, как день 1, а в дне 7 появляется итоговый тест недели 1. Полный день — это теория (мысли со схемами и ссылками в книгу, тренажёр или ситуация, ИИ на странице), тест, практика, наставник и карточки.

**Architecture:** содержание дня — данные в `course/content/days/day-NN.json`, схема `src/content/schema.ts`. Код меняется только в Задаче 1: поле `weekTest`, его показ и проверки содержания, которых не хватает. Задачи 2–7 — по одному дню: JSON дня, пересборка `content/graph.json` и чек-листа наставника, правка ожиданий в тестах-сводках. Задача 8 — e2e, сборка, публикация.

**Tech Stack:** Vite, React 19, TypeScript, Zod, Vitest, Playwright 1.56.1.

**Spec:** `docs/superpowers/specs/2026-10-21-interactive-course-design.md`, §2 «Программа», §3 «Как устроен день», §8 фаза 2, §9 «Проверка качества».

**Факты для исполнителей:** `.superpowers/sdd/2026-11-04-book-in-course/week1-theory-research.md`. Там: схема, правила проверок, образец дня 1, разделы книги по дням (§5), схемы (§6), словарь (§7), наставник (§8), сессии роликов по дням (§9), граф (§10), тесты под угрозой (§11).

## Global Constraints

- Язык — русский. Пишем просто, как знающий человек говорит с новичком: короткие прямые фразы, без канцелярита.
- Каждая мысль и каждый вопрос теста сверены с книгой `vibe-coding-na-praktike-2026-10.html`: факт без опоры в книге не пишется (спецификация §9).
- Блоки `video` дня остаются первыми, в прежнем порядке. `title` и `goal` дней не меняются: в таблице задач — краткие темы, а не новые названия.
- Мыслей (`idea`) — 3–5. Текст мысли — 500–700 знаков, 2–3 абзаца через `\n\n`, пример — из приложения тренера (Марина, Анна, Олег).
- У каждой мысли есть `bookRef: {section, label}`:
  - `section` — id раздела `h3` (`s14`…`s92`, `sa1`…`sa7`);
  - `label` — «Гл. N: <раздел строчными, коротко>»;
  - внутри дня раздел не повторяется.
- Схема (`figure` у `idea` или `diagram`) — только из тех, что стоят в тексте книги (блок `t:"fig"`). Внутри дня схема не повторяется. Схем в дне — не меньше двух.
- В дне не меньше одного тренажёра или одной ситуации — по таблице задач ниже. Ещё в дне один блок `ai-helper` в конце теории: `context` — около 1000 знаков о теме дня, как в дне 1.
- Тест — 5–7 вопросов по 4 варианта. `explanation` — 150–220 знаков, кончается ссылкой в скобках: «(гл. 7, «Политики доступа к строкам»).»
- Практика — 4–7 шагов для **своего** проекта ученика `trainer-app` на стеке спецификации §7:
  - стек: Next.js 16, TypeScript strict, Supabase, Vercel, Vitest, Playwright;
  - `prompt` — готовый запрос для Claude Code, 110–400 знаков;
  - `done` — проверяемый критерий, 70–120 знаков.
- Запросы практики безопасны:
  - ключи и пароли не вставляются в чат;
  - миграции и удаление — «с моего подтверждения»;
  - без `--force` и `reset --hard`;
  - секреты — в `.env.local` и в переменных Vercel.
- Наставник:
  - `command` — `/mentor N`;
  - `checklist` — 3–5 пунктов, `auto` где можно (`tests` | `lint` | `secrets` | `rls` | `file`);
  - `questions` — 2–3 вопроса про код ученика.
- Карточки — 6–12 точных терминов из `content/glossary.json`, без повторов в дне.
- `status: "ready"`, `minutes: {theory: 40, practice: 80}`, `result` — одна фраза: что у ученика есть к концу дня.
- Все `id` внутри дня уникальны: блоков, вопросов, шагов, пунктов наставника, карточек тренажёра, корзин, узлов, частей.
- После правки дня — `npm run build:graph` и `npm run build:mentor`. Сгенерированные `content/graph.json` и `../mentor/days/day-NN.md` коммитятся вместе с днём.
- Проверка перед коммитом из `course/`: `npm test`, `npm run lint`, `npx tsc -b`. В Задаче 8 ещё `npm run e2e`.
- Если поисковый тест падает, потому что новое содержание встало выше по рангу, поправить тест, а не переименовывать содержание.
- Коммиты кончаются строками `Co-Authored-By: Claude Opus 5.5 <noreply@anthropic.com>` и `Claude-Session: https://claude.ai/code/session_01DQgsSEqLgHui6HevL5dFCC`. Ветка `course/theory-days`.

## Review Focus

1. **Запросы практики, которые навредят проекту ученика.** Сюда относятся: ключ в чате, миграция без подтверждения, разрушительный git, `NEXT_PUBLIC_` у секрета. Ревьюер читает каждый `prompt` как новичок, который выполнит его дословно.
2. **Мысль или вопрос не из книги.** Опасны и `bookRef` на раздел, где об этом нет. Ревьюер сверяет каждую мысль и каждое объяснение с разделом, на который они ссылаются.
3. **Практика расходится с роликом дня.** Ролик показывает демо на локальном Postgres. Практика ученика — на настоящем Supabase и Vercel, и шаги не должны требовать демо-команд (`psql` к локальной базе, `supabase/tests/as-marina.sql` демо). При этом слова и порядок не должны противоречить тому, что ученик только что видел.
4. **Итоговый тест недели спрашивает то, чего в днях 1–7 нет.** Каждый вопрос `weekTest` опирается на мысль или тест одного из дней 1–7.
5. **Сохранённый прогресс ученика после выкладки.** Ответы и галочки дня 1 и черновиков не пропадают, а тест недели хранится отдельно от теста дня 7. Тест — Задача 1.
