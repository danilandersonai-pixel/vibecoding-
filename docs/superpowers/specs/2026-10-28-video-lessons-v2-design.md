# Видеоуроки в стиле «Репозиторий» — дизайн

Переделка всех 27 видеоуроков курса в лучшем качестве. Заменяет в спецификации `2026-10-21-video-lessons-design.md` разделы 3 «Как устроен ролик», 4 «Набор для анимации» и 5 «Сайт» для переделанных роликов. Темы, дни и порядок роликов остаются прежними (раздел 2 той спецификации).

Ветка — `video/terminal` от `design/terminal`; светлый курс в `claude/interactive-course` со старыми роликами не меняется.

## 1. Цель и рамки

- Те же 27 тем. Лучше становятся три вещи: чёткость кадра, живость анимации, сценарий.
- Стиль — вид курса «Репозиторий»: тёмный монохромный интерфейс-инструмент. Героев нет: в кадре только экраны — терминал, редактор, чат с агентом, дифф, история git, страница в браузере, схемы книги.
- Примеры — настоящая работа над приложением тренера: оно собирается по шагам в папке `demo-app/`. Команды, их вывод, диффы и коммиты записываются в файлы и в ролике проигрываются анимацией. Придуманного вывода в кадре нет.
- Звук прежний: голос браузера по желанию, в кадре — субтитры. MP4 для скачивания больше нет.
- Работа идёт пилотом: основа (запись сессий, набор кадров, урок как данные, главы в плеере) и два ролика дня 1 — `ch-abc` и `ch-01`. Автор утверждает стиль по пилоту; остальные 25 роликов — потом, по неделям, отдельным планом.

Успех пилота: автор посмотрел `ch-abc` и `ch-01` на странице дня 1 и сказал «так и делаем». Технически: оба ролика проходят проверки урока (раздел 9), каждый показанный вывод команды взят из записи, на перемотке видны главы.

## 2. Что согласовано с автором

- Кадр 1920 × 1080, 30 кадров/с, текст в кадре не мельче 24 px.
- Каркас каждого урока: что узнаете → объяснение → пример → типичная ошибка → итог. Главы видны внутри ролика и на полосе перемотки.
- Точнее по книге: факты, цифры и схемы — из указанных разделов, в кадре ссылка на раздел.
- Длина как сейчас (ролик главы 3–4,5 мин, ролик дня 1–3 мин) и не короче прежнего ролика той же темы. Реплики по-русски, темп прежний.
- Плеер: главы на перемотке (новое), пояснения по нажатию, субтитры и голос. Кнопки «Скачать MP4» у новых роликов нет.
- Приложение тренера — папка этого репозитория, только как источник записей.

## 3. Решения, принятые без автора

Каждое решение можно поменять при утверждении пилота.

- **Облако.** Docker в контейнере не запускается, поэтому локального Supabase нет. Шаги, которым нужен Supabase, Vercel или GitHub, записываются на локальных заменах, когда они есть (Postgres 16 из `/usr/lib/postgresql/16/bin` — для SQL и RLS). Если замены нет, сцена рисует схему книги, а не придуманный вывод. В пилоте облако не нужно.
- **Слова агента.** Запрос к агенту и его ответ пишет автор сценария; всё, что агент делает (читает файлы, правит, запускает команды, коммитит), выполняется по-настоящему и записывается. В записи такие шаги помечены `by: "agent"`.
- **Интерфейс Claude Code в кадре** — как на схемах книги `ch1_agent_session` и `dk_modes`: строки «Reading …», «Edited … (+N −M)», вопрос `Run "…"? [y / n]`, режимы Plan / Manual / Accept edits. Другие английские строки интерфейса не выдумываются; где книги не хватает — короткие русские подписи.
- **Порядок записей.** Записи не обязаны идти день в день с практикой курса: Азбука показывает заготовку Next.js раньше, чем её делают на практике. Записи идут цепочкой, каждая продолжает предыдущую.
- **Старые ролики в ветке.** Переделанный ролик заменяет старый в каталоге под тем же id, папка старого ролика удаляется (она остаётся в истории git и в светлом курсе). Остальные ролики до своей очереди остаются прежними — светлыми, 1280 × 720, с MP4.
- **Тема ролика всегда тёмная**, как терминал в курсе: переключатель темы сайта на кадр не влияет.
- **Шрифты в кадре** — те же, что у курса: Golos Text для текста и субтитров, Martian Mono для экранов. Сайт берёт их из Google Fonts, а рендер кадров для проверки — из пакетов `@fontsource-variable/golos-text` и `@fontsource-variable/martian-mono` (только для Remotion, в сборку сайта не попадают).
- **Схемы книги в кадре** — те же SVG из `course/content/figures/`, подключаются как в курсе (`?raw`) и красятся тёмными токенами.
- **Главы в плеере** — сегменты на полосе перемотки и список глав кнопками под роликом; нажатие на главу перематывает к её началу и запускает ролик.

## 4. Приложение тренера и записи сессий

### 4.1 Что где лежит

- `demo-app/sessions/<id>.mjs` — шаги одной сессии (список ниже). Id сессии — `sNN-слово`: `s01-start`, `s02-sets`.
- `course/scripts/record-session.mjs <id>` — проигрывает цепочку сессий до `<id>` во временной папке, по-настоящему выполняет шаги и пишет запись `course/video/sessions/<id>.json`. После последней сессии копирует рабочее дерево (без `.git`, `node_modules`, `.next`) в `demo-app/app/`.
- `demo-app/app/` — исходники приложения тренера в состоянии последней записанной сессии. Отдельно не правится: меняется только записью.
- `demo-app/README.md` — что это за папка и как перезаписать сессии.

Перезапись — явное действие автора или исполнителя плана; тесты команды не запускают, а проверяют уже сделанные записи.

### 4.2 Шаги сессии

```js
export default {
  id: 's02-sets',
  from: 's01-start',        // какая сессия идёт перед этой; null — первая
  steps: [
    { id: 'dev', run: 'npm run dev', until: 'Ready' },            // команда; until — для долгих, ждать строку и оставить работать
    { id: 'route', write: 'app/api/sets/route.ts', content: '…' }, // новый файл или полная замена
    { id: 'fix', edit: 'app/api/sets/route.ts', find: '…', replace: '…' },
    { id: 'c3', commit: 'Сохранение подхода: проверка веса' },
    { id: 'ask', agent: { prompt: '…', reply: '…' }, steps: [ /* шаги агента */ ] },
    { id: 'save', browser: { url: '/', fill: { 'Вес, кг': '60 кг' }, click: 'Сохранить подход' } },
  ],
}
```

- `run` — команда в оболочке из корня проекта; записываются команда, вывод (stdout и stderr по порядку) и код выхода. С `until` команда остаётся работать до конца сессии (dev-сервер).
- `write`, `edit` — правка файла; записывается настоящий `git diff` этой правки.
- `commit` — `git add -A` и `git commit`; записываются короткий хеш, сообщение, вывод и список файлов с хешами blob.
- `agent` — ход агента: запрос и ответ (авторский текст) и вложенные шаги, которые помечаются `by: "agent"`.
- `browser` — Playwright открывает страницу работающего dev-сервера, заполняет поля, нажимает кнопки; записываются заголовок и видимые подписи страницы, сообщения консоли и ответы сети с кодом 400 и выше.

Чтобы запись повторялась, git получает постоянные имя, почту и время коммитов (`GIT_AUTHOR_*`, `GIT_COMMITTER_*`: «Анна», `anna@example.com`, время сессии + минута на коммит). Версии пакетов закреплены (`create-next-app@16.4.3`).

### 4.3 Запись

```json
{
  "id": "s02-sets", "from": "s01-start", "recorded": "2026-10-28",
  "events": [
    { "id": "dev", "kind": "run", "cmd": "npm run dev", "out": ["…"], "code": null },
    { "id": "route", "kind": "file", "path": "app/api/sets/route.ts", "diff": ["@@ …", "+…"], "blob": "<sha1>" },
    { "id": "c3", "kind": "commit", "hash": "3f2a9c1", "message": "…", "out": ["…"], "files": [{ "path": "…", "blob": "<sha1>" }] },
    { "id": "ask", "kind": "agent", "prompt": "…", "reply": "…", "steps": ["read1", "fix", "test"] },
    { "id": "save", "kind": "browser", "url": "http://localhost:3000/", "title": "…", "text": ["…"], "console": [{ "type": "error", "text": "…" }], "network": [{ "status": 400, "url": "…" }] }
  ]
}
```

- Вывод очищается от управляющих последовательностей цвета; временная папка в путях заменяется на `~/trainer-app`. Других правок вывода нет.
- Строки вывода хранятся как есть; длинные строки кадр переносит сам (раздел 5.3).

### 4.4 Проверка записей

Тест `course/video/sessions/sessions.test.ts`:

- у каждого события есть уникальный id, у сессии с `from` есть запись предыдущей;
- диффы, применённые по порядку к содержимому из предыдущих событий, дают файлы с записанными хешами blob (хеш считается как в git: `sha1("blob <длина>\0<содержимое>")`);
- файлы последнего коммита последней сессии совпадают по хешам с `demo-app/app/`;
- каждый шаг агента ссылается на событие той же сессии.

## 5. Набор кадров «Репозиторий» (`course/video/term/`)

### 5.1 Холст

- 1920 × 1080, фон `desk` #141619. Цвета — тёмные токены курса, без собственных: `paper` #1A1D21 (окна), `raised` #22262B, `edge` #2B3036, `ink` #E9EBEE, `ink-soft` #A3A9B1, `ink-faint` #868D96, линии `fig-line` #7A818A, сетка `fig-grid` #3A4048, терминал `term-bg` #0F1113. Цвет только у состояний, как в диффе: `ok` #5BC78F, `err` #F07C70, `warn` #E3B45C. Выделение — инверсией или рамкой `ink` 2 px.
- Поля кадра: содержимое в прямоугольнике x 96–1824, y 96–872.
- Шапка кадра (y 32–80, Martian Mono 24 px, `ink-faint`): слева id ролика и глава «02/07 · Git: история проекта», справа ссылка на книгу «книга · Азбука § 3».
- Субтитры: полоса y 896–1040, Golos Text 500 40 px/1.4, не больше двух строк и 1500 px в ширину, плашка `term-bg` 88 %, скругление 6 px.
- Текст не мельче 24 px; моноширинный — Martian Mono, обычный — Golos Text. Линии не тоньше 2 px.

### 5.2 Движение

Кривые — из дизайн-системы: появление `ease-out` cubic-bezier(.16,1,.3,1), уход `ease-in` (.5,0,.75,0). Длительности для видео:

| Что | Кадров |
|---|---|
| Появление элемента | 9 |
| Перемещение камеры, смена окна | 18 |
| Прорисовка линии схемы | 19 |
| Шаг очереди строк вывода | 2 |
| Набор команды | 30 знаков/с, курсор мигает раз в 16 кадров |
| Смена сцены внутри главы | 8 (растворение и сдвиг на 16 px) |
| Смена главы | 12 (полоса главы в шапке, номер прокручивается) |

Каждые 3–4 секунды в кадре что-то меняется: строка, подсветка, движение камеры.

### 5.3 Кадры

Каждый кадр — компонент с чистой функцией разметки: по данным сцены он считает прямоугольники своих частей (строка вывода, строка диффа, коммит, кнопка). На эти имена ссылаются камера и пояснения по нажатию.

| Кадр | Что показывает | Данные |
|---|---|---|
| `Terminal` | команды набираются, вывод идёт строками, окно прокручивается | события `run` |
| `Editor` | дерево файлов и файл; подсветка строк, набор новых строк | файл на событии `file` или `commit` |
| `Diff` | настоящий дифф: убранное `err`, новое `ok`, заголовок файла и «+N −M» | событие `file` или `commit` |
| `Agent` | сессия Claude Code: запрос, «Reading …», «Edited … (+N −M)» с диффом, вопрос `[y / n]`, ответ | событие `agent` и его шаги |
| `GitLog` | история: коммиты точками с хешем, ветки линиями, HEAD; откат | события `commit` |
| `Browser` | страница localhost (заголовок, подписи, поля, кнопки — векторно) и панель Console | событие `browser` |
| `Figure` | схема книги: части появляются по очереди, линии прорисовываются, фокус приглушает остальное | id схемы |
| `Board` | таблица, шкала или карточки для понятий без записи (режимы, цены) | данные сцены |
| `Agenda` | «Что узнаете»: список глав ролика строками, как лог | главы урока |
| `Recap` | «Итог»: по выводу на главу и ссылка на разделы книги | урок |

- Длинная строка переносится по ширине окна (Martian Mono 24 px, ширина знака 0,6 em); сцена может показать часть вывода — диапазон строк, но не может их менять.
- Сцена с ролью «ошибка» получает метку «Типичная ошибка» цвета `err` в шапке; кадр показывает неверный вариант, затем верный (`ok`).
- Схема книги масштабируется так, чтобы самый мелкий её текст (11,5 px) был не меньше 24 px: ширина схемы 760 → не меньше 1590 px.

## 6. Урок как данные

### 6.1 Описание урока

`course/video/lessons/<id>/lesson.ts`:

```ts
type Lesson = {
  id: string                      // 'ch-abc'
  kind: 'chapter' | 'day'
  title: string
  book: string[]                  // разделы книги: ['sa1', …]
  chapters: LessonChapter[]       // первая — «Что узнаете», последняя — «Итог»
}
type LessonChapter = { id: string; title: string; book?: string[]; scenes: LessonScene[] }
type LessonScene = {
  id: string
  role: 'intro' | 'explain' | 'example' | 'mistake' | 'summary'
  frame: FrameSpec                // какой кадр и его данные (раздел 5.3)
  lines: string[]                 // реплики; из них считается время
  actions?: Action[]              // { at: номер реплики, do: 'type' | 'show' | 'focus' | …, target?: имя части кадра }
  camera?: { at: number; target: string | 'whole'; zoom?: number }[]
  spots?: { at: number; until?: number; target: string; title: string; text: string }[]
}
```

- Время — из реплик, как сейчас (`PACE`: 14 знаков/с, вступление 0,3 с, пауза 0,25 с, хвост сцены 1 с, реплика не короче 2,2 с). Действия, камера и пояснения привязаны к номеру реплики, поэтому правка текста не рассинхронизирует картинку.
- `buildLesson(lesson)` выдаёт `VideoScript` 1920 × 1080 с репликами, пояснениями (прямоугольники — из разметки кадра и камеры) и главами `{ from, title }`.
- Ролик — один общий компонент `LessonVideo`; у урока остаётся `Video.tsx` из одной строки, чтобы код урока грузился лениво, как сейчас.

### 6.2 Каркас

- Ролик главы: «Что узнаете» (кадр `Agenda`), 3–5 тематических глав, «Итог» (кадр `Recap`). В каждой тематической главе по порядку: объяснение, пример на приложении тренера, типичная ошибка.
- Ролик дня: «Что строим сегодня» (`Agenda`), «Пример», «Подводный камень» (роль «ошибка»), «Проверьте у себя» (`Recap`).
- В каждой тематической главе ролика главы есть хотя бы один кадр с записью (`Terminal`, `Editor`, `Diff`, `Agent`, `GitLog`, `Browser`), где тема это позволяет; в ролике дня — во «Примере».
- Пояснений по нажатию: у ролика главы не меньше 2, у ролика дня не меньше 1.

## 7. Плеер

- `VideoScript` получает размер 1280 × 720 или 1920 × 1080 и необязательные главы `chapters: { from: number; title: string }[]`. Старые ролики работают как раньше.
- Полоса перемотки делится на сегменты по главам (зазор 2 px), заполненная часть — `ink`. Рядом со временем — текущая глава: «3/7 · Git: история проекта».
- Под роликом — список глав кнопками: время начала и название. Нажатие перематывает к началу главы и запускает ролик. Текущая глава отмечена.
- Пояснения по нажатию считают проценты от размера кадра ролика, а не от 1280 × 720.
- Обложка — кадр середины первого примера урока.
- Новые ролики не имеют MP4: адресов в `registry.ts` для них нет, кнопки «Скачать MP4» нет.
