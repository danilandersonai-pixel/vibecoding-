# Интерактивный курс по книге «Вайб-кодинг на практике» — дизайн

Дата: 21.10.2026 · Статус: на согласовании

## 1. Цель и рамки

**Что сказал автор курса (он же единственный ученик):**
- курс делается для себя, а не для продажи или других учеников;
- результат — и уверенное знание материала, и свой работающий проект;
- около 2 часов в день; курс растянут на 2–3 недели;
- сквозной проект — веб-приложение с двумя ролями: тренер в зале отслеживает прогресс подопечных, подопечный вписывает свои результаты;
- в проекте нужен раздел питания;
- форма курса — сайт и наставник в Claude Code;
- в теории нужны живые схемы, тренажёры, ситуации с выбором, ИИ на странице и объясняющие видео, сделанные на JavaScript (не анимированные слайды и не пересказ книги);
- видео играет в плеере на странице и выгружается в MP4;
- начать с пилотного ролика;
- детали самого приложения обсудим отдельно.

**Предположения (поправить при ревью):**
- источник материала — книга `vibe-coding-na-praktike-2026-10.html` в этом репозитории, глава 12 включена;
- курс на русском языке;
- автор проходит курс в Claude Code (приложение на компьютере или облачные сессии) и открывает сайт курса в Claude на компьютере и телефоне;
- неделя 3 может сокращаться, если первые две займут больше времени.

**Критерии успеха:**
- к концу дня 7 — первая версия приложения выложена в интернет, работает на телефоне, тренер видит только своих подопечных, пройден итоговый тест недели 1;
- к концу дня 21 — приложение готово к бета-тесту и запуску, есть план развития;
- все 12 глав и «Азбука» пройдены, по каждому дню пройден тест и принята практика наставником.

## 2. Программа

## 3. Как устроен день

Каждый день — одна страница сайта из шести блоков.

1. **Зачем сегодня.** Цель и результат дня.
2. **Теория.** Объясняющее видео дня, затем 3–5 ключевых мыслей своими словами с живыми схемами и ссылками в нужное место книги. Внутри теории — тренажёры и ситуации с выбором.
3. **Проверка понимания.** 5–7 вопросов с выбором ответа, мгновенная проверка и объяснение, можно перепроходить.
4. **Практика.** Шаги с галочками; у каждого шага готовый запрос для Claude Code с кнопкой «скопировать» и критерий «готово».
5. **Наставник.** Команда для Claude Code, которая проверяет практику дня в проекте и задаёт 2–3 вопроса про код автора.
6. **Итог дня.** Заметки и карточки новых терминов; карточки с отметкой «повторить» возвращаются в следующие дни.

По всему курсу: карта 21 дня с отметками, серия дней подряд, итоговые тесты в конце недель.

### Интерактивные элементы теории

| Элемент | Как работает | Пример |
|---|---|---|
| Живая схема | Нажатие на часть схемы раскрывает пояснение; процессы идут по шагам кнопкой «дальше» | Путь нажатия «Сохранить» от кнопки до базы |
| Тренажёр «собери запрос» | Автор собирает запрос из блоков ЦКОКФ, страница подсвечивает пропущенные элементы | Запрос «добавь график прогресса» |
| Тренажёр «найди ошибку» | Нажатие на опасную строку кода или диффа | Секрет в коде, проверка без владельца |
| Тренажёр «расставь по матрице» | Перетаскивание задач по матрице «цена ошибки × лёгкость проверки» | Что доверить агенту в проекте тренера |
| Ситуация с выбором | Короткая история с ветвлениями: выбор действия и его последствия | Агент удалил тест, чтобы проверки стали зелёными |
| ИИ на странице | Оценивает запрос автора по ЦКОКФ, отвечает на вопросы по теме дня в рамках материала дня | «Почему RLS, а не проверка в интерфейсе?» |

Без ИИ (курс открыт вне Claude) всё, кроме последней строки, работает; блок ИИ показывает пометку «доступно в Claude».

## 4. Видео

**Стиль.** Объясняющие ролики со своим сценарием: герой, наглядная метафора, демонстрация на примере приложения тренера, развязка «проверьте у себя». Не пересказ книги и не слайды. Длина — 3–5 минут на день недели 1; в неделях 2–3 — 1–3 минуты там, где тема выигрывает от показа.

**Техника.**
- Ролики пишутся на Remotion (версия 4, бесплатна для частных лиц). Общая библиотека «актёров» и декораций: тренер, подопечный, телефон, сервер, база данных, турникет-RLS, агент, терминал.
- Ролик = сценарий (реплики с таймингами) + композиция из сцен.
- На странице ролик играет в плеере Remotion: пауза, перемотка, субтитры, «горячие точки» — нажатие на объект в кадре на паузе показывает пояснение.
- Голос в плеере — синтез речи браузера (Web Speech API), реплики запускаются по таймингам сцен; если русского голоса нет — только субтитры.
- MP4 — рендер командой (720p, сжатие под лимит хранилища 20 МБ на файл). Голос для MP4 решаем после пилота: без голоса с субтитрами или сервис озвучки.

**Пилот.** Ролик дня 4 «Почему тренер не увидит чужих подопечных» (RLS и IDOR), пять сцен:
1. Два тренера и их подопечные.
2. Запрос идёт от кнопки к серверу и в базу.
3. Злоумышленник меняет `client/17` на `client/18`.
4. RLS как турникет в зале пропускает только свои записи.
5. «Проверьте у себя за 2 минуты».

После пилота автор утверждает стиль, темп и голос, и только потом делаются остальные ролики.

## 5. Сайт курса: устройство

**Где.** Папка `course/` в репозитории `vibecoding-`.

```
course/
  content/
    days/day-01.json … day-21.json   — содержание дней (данные, не код)
    figures/                          — схемы, извлечённые из книги
    glossary.json                     — термины для карточек
  src/                                — приложение на React (Vite)
    components/                       — блоки дня и интерактивные элементы
    services/progress.ts              — хранение прогресса
    services/ai.ts                    — вызовы ИИ
  video/                              — проект Remotion: актёры, сцены, ролики
  scripts/                            — извлечение схем из книги, сборка, проверки
mentor/                               — навык наставника для копирования в проект приложения
```

**Содержание дня как данные.** Файл дня описывает блоки по типам: `goal`, `video`, `idea` (текст + схема + ссылка в книгу), `diagram`, `trainer` (подтип и данные), `scenario` (узлы и переходы), `quiz` (вопросы, варианты, верный ответ, объяснение), `practice` (шаги, запрос, критерий «готово»), `mentor` (команда и чек-лист), `cards`. Формат проверяется схемой при сборке: опечатка в данных ломает сборку, а не страницу.

**Ссылки в книгу.** Книга лежит рядом с курсом; ссылка открывает её на нужном разделе по идентификатору раздела (`s77` и т. п.). Если движок книги не умеет открываться по адресу с якорем, в книгу добавляется чтение якоря при загрузке.

**Прогресс.** Один интерфейс, два хранилища:
- в Claude — личная база страницы (`db`), путь `data/users/<id>/progress`, видна только автору; её же может читать Claude через `ArtifactData`;
- вне Claude — хранилище браузера.

Что хранится: пройденные шаги и дни, ответы на тесты и лучший результат, отметки наставника, заметки, карточки «повторить», серия дней.

**ИИ.** Через возможность страницы `sample`. Каждый вызов несёт инструкцию, материал текущего дня и формат ответа; вызывается только по нажатию кнопки. Отказ или лимит — понятное сообщение, без повторов в цикле.

**Публикация.** Сборка Vite → статические файлы → приватная страница Claude с возможностями `sample`, `db`, `user`, `assets`. MP4 загружаются в хранилище страницы. Исходники — в git.

**Оформление.** Те же шрифты и цветовые токены, что в книге, светлая и тёмная тема, работа на ширине телефона.

## 6. Наставник

- **Где.** Навык Claude Code в репозитории приложения автора: `.claude/skills/mentor/SKILL.md` и чек-листы дней `.claude/skills/mentor/days/day-NN.md`. Чек-листы генерируются из тех же файлов дней, что и сайт. Установка — шаг практики дня 1 (готовый запрос копирует папку из репозитория курса).
- **Вызов.** `/mentor 5` — проверить день 5.
- **Что делает.**
  1. Читает чек-лист дня.
  2. Запускает автоматические проверки, которые есть на этот день: тесты, линтер, поиск секретов, попытка открыть чужие данные вторым пользователем.
  3. Задаёт 2–3 вопроса про код автора и разбирает ответы.
  4. Если что-то не готово — даёт подсказку, а не готовое решение.
  5. Записывает итог в `mentor-log.md` в репозитории приложения. Отметку «день принят» на сайте в фазе 1 ставит сам автор переключателем; автоматическая отметка из Claude Code — после проверки, что наставник может писать в базу курса.

## 7. Приложение для тренера: рамки для курса

- Одно веб-приложение с двумя ролями, устанавливается на телефон (PWA).
- Стек книги: Next.js 16, TypeScript в строгом режиме, Supabase (база, вход, RLS, хранилище файлов), Vercel, тесты на Vitest и Playwright.
- Первая версия (день 7): вход двух ролей, тренер добавляет подопечного и назначает тренировку, подопечный вписывает подходы, повторы и веса, тренер видит график прогресса, доступ к данным закрыт политиками, приложение выложено.
- Недели 2–3 — по программе раздела 2, включая питание (день 16).
- Детали приложения — эталоны, отличие, модель данных, экраны — обсуждаются отдельно до старта дня 2 и не входят в этот документ.

## 9. Проверка качества

- **Содержание:** каждая мысль и вопрос теста сверены с книгой; у каждого вопроса одно верное объяснение; запросы практики проверены на учебной копии проекта.
- **Сайт:** автотесты в браузере (Playwright) — открыть день, пройти тест, отметить шаг, перезагрузить и увидеть сохранённый прогресс; проверка на ширине телефона, в светлой и тёмной теме; сборка без ошибок схемы данных.
- **Видео:** рендер пилота в MP4, проверка длительности, размера (до 20 МБ) и синхронизации субтитров; плеер на странице — пауза, перемотка, горячие точки.
- **Наставник:** прогон `/mentor 1` на учебном проекте с заведомо невыполненным и выполненным шагом.
