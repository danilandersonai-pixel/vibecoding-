# Набор «Репозиторий»: правила для следующих роликов

Тёмные ролики 1920 × 1080, 30 кадров/с, в стиле курса «Репозиторий»: в кадре только экраны (терминал, редактор, дифф, агент, история git, браузер) и схемы книги. Образцы — `video/lessons/ch-abc` и `video/lessons/ch-01`. Спецификация — `docs/superpowers/specs/2026-10-28-video-lessons-v2-design.md`; здесь то, что к ней добавил пилот. Все команды — из `course/`.

## Карта

| Где | Что |
|---|---|
| `video/lessons/<id>/` | урок: `lesson.ts` (данные), `lesson.test.ts`, `script.gen.json` (снимок сценария для сайта), `script.ts` (читает снимок), `Video.tsx` (одна строка, ленивый кусок) |
| `video/term/` | набор: `frames/` (10 кадров), `chrome/` (шапка, субтитры, вердикт), `build.ts` (`buildLesson`), `problems.ts` (`lessonProblems`), `theme.ts` (цвета и движение), `lesson.ts` (типы урока и ловушки) |
| `video/sessions/*.json` | записи сессий — источник всего показанного вывода; руками не правятся |
| `../demo-app/sessions/*.mjs` | шаги сессий; `../demo-app/app/` — приложение тренера после последней сессии (правится только записью) |
| `scripts/` | `record-session.mjs`, `print-event.mjs`, `lesson-stills.mjs` |

Цвета кадра — только из `theme.ts`; текст не мельче 24 px, линии не тоньше 2 px; содержимое в SAFE (x 96–1824, y 96–872), шапка y 32–80, субтитры y 896–1040. Если кадр не по правилам, `lessonProblems` скажет сам.

## 1. Каркас (спецификация §6.2)

**Ролик главы** (5400–8100 кадров, не короче прежнего ролика той же темы):

1. «Что узнаете» — одна сцена `intro`, кадр `agenda`.
2. 3–5 тематических глав. В каждой по порядку: `explain` (схема или доска) → `example` (запись на приложении тренера) → `mistake` (типичная ошибка: неверный вариант, затем верный).
3. «Итог» — одна сцена `summary`, кадр `recap`.

Кадр записи (`terminal`, `editor`, `diff`, `agent`, `gitlog`, `browser`) — не меньше чем в трёх тематических главах (спецификация говорит «в каждой, где тема позволяет»; проверка мягче). Пояснений по нажатию — не меньше 2.

**Ролик дня** (1800–5400 кадров): главы строго «Что строим сегодня» (`intro`) → «Пример» (`example`, хотя бы один кадр записи) → «Подводный камень» (`mistake`) → «Проверьте у себя» (`summary`). Пояснений — не меньше 1.

**Сцена `mistake`.** В шапке метка «Типичная ошибка». Нужны вердикты `verdict: [{ at, kind: 'wrong' }, { at, kind: 'right' }]` — «Неверно», потом «Верно». Ошибку можно разбить на серию сцен `mistake` подряд: достаточно одного `wrong` и одного `right` на серию, `wrong` раньше. Сцены серии без своих вердиктов показывают в шапке вердикт предыдущей (без мигания на смене сцен).

Каждая тематическая глава указывает `book` (разделы книги: `sa1`, `s5`…), сцена из другого раздела — свой `book`. Факты, цифры и названия — из этих разделов; при расхождении права книга. Слова агента (запрос, ответ) и содержимое файлов, которые он пишет, — авторский текст, всё остальное в кадре — из записей.

## 2. Единицы в данных урока

- **Реплика** — строка в `lines` сцены. Время считается из реплик (`PACE`: 14 знаков/с, вступление 0,3 с, пауза 0,25 с, хвост 1 с, реплика не короче 2,2 с): реплика ≈ `max(2,2; знаков / 14 + 0,4)` с. Первая реплика начинается на 9-м кадре сцены.
- **`at`** (во всех кадрах, в `camera`, `spots`, `verdict`) — номер реплики сцены с 0: действие приходит на её начало. Правка текста реплики не рассинхронизирует картинку; перестановка реплик — рассинхронизирует.
- **`lines`, `highlight.lines`, `consoleLines`, `code`** — диапазон `[от, до]` номеров строк с 1, оба конца включены. Номера у каждого кадра свои, свериться можно только по `print-event.mjs` (раздел 4): `terminal` — строки вывода события; `editor` — строки файла после правки; `diff` — строки диффа от первой «@@» (она — 1); `browser.consoleLines` — сообщения консоли «как в DevTools».
- **Части кадра** — цели `camera` и `spots`. Имена: `frame`; `terminal` — `cmd:<событие>`, `out:<событие>`, `line:<событие>:<k>` (k с 0 среди показанных); `editor` — `tree`, `code`, `line:<n>` (n — номер строки файла); `diff` — `file:<событие>`, `line:<событие>:<k>`; `agent` — `prompt`, `step:<id шага>`, `reply`, `code` (у чата), `mode`; `gitlog` — `commit:<событие>`, `head:<ветка>`, `dirty`; `browser` — `url`, `page`, `field:<подпись>`, `button:<текст>`, `console`, `console:<k>`; `figure` — `focus:<имя>`; `board` — `title`, `row:<k>`, `card:<k>`, `item:<k>`, `marker`, `marker-label`; `agenda`, `recap` — `item:<k>`, у `recap` ещё `book`.
- **Части — снимок конца сцены**: когда всё появилось и (у терминала) прокручено. Камера и пояснение смотрят туда, где часть стоит в конце, а не в момент реплики.
- **Камера**: `camera: [{ at, target }]` — с реплики `at` наезд на часть (`'whole'` — весь кадр). **Пояснение**: `spots: [{ at, until?, target, title, text }]` — открывается на реплике `at`, закрывается на `until` (без него — за 12 кадров до конца сцены). Рамка пояснения берётся из разметки кадра и камеры.

## 3. Кадры

Поля — в `frames/*Plan.ts` (там же подробные doc-комментарии, их читать перед первым использованием кадра).

| Кадр | Что показывает | Главные поля |
|---|---|---|
| `terminal` | команды набираются, вывод идёт строками, окно в 19 строк прокручивается; у события `browser` — строки `server` продолжением вывода | `items: [{ session, event, at, lines? }]`, `title?` |
| `editor` | дерево файлов и файл с номерами строк (в окне 18 строк с переносом); подсветка, набор новых строк, серая подсказка | `session`, `event` (`file`/`read`), `tree: { session, commit }`, `lines`, `highlight: [{ at, lines }]`, `typing`, `ghost: { at, accept }` |
| `diff` | настоящий дифф: убранное `err`, новое `ok`, «+N −M»; до 18 строк на файл | `items: [{ session, event, at, lines? }]`, `highlight: [{ at, event, lines }]` |
| `agent` | сессия Claude Code: запрос, `Reading …`, `Edited … (+N −M)` с диффом, `Run "…"? [y / n]`, ответ; `chat: true` — окно «Чат с ИИ» | `session`, `event`, `mode` (`Plan`/`Manual`/`Accept edits`), `ask`, `diffLines` (число или `{ id шага: строк }`), `chat`, `code`, `at: { prompt, steps[], reply }` — по реплике на каждый шаг записи |
| `gitlog` | история как `git log --graph`: коммиты точками, ветки линиями, метки веток | `rows: [{ session, event, at }]`, `heads: [{ at, branch, commit }]`, `dirty` |
| `browser` | страница localhost векторно + панель Console | `session`, `event`, `console`, `consoleLines`, `marks: [{ line, tone }]`, `at: { page, action?, console? }` |
| `figure` | схема книги (`?raw`); части появляются по очереди, фокус приглушает остальное | `svg`, `crop` (чтобы мелкий текст схемы вырос до 24 px), `reveal`, `focus: [{ at, name, rect }]` |
| `board` | таблица, карточки, шкала для понятий без записи | `title`, `table`, `cards`, `scale` |
| `agenda` | «Что узнаете»: главы урока строками | `at?: number[]` |
| `recap` | «Итог»: выводы с галочкой и разделы книги | `items: [{ text, at }]` |

## 4. Записи сессий

- **Сессия** — `../demo-app/sessions/sNN-слово.mjs`: `export default { id, from, steps }`. Шаги: `run` (команда; `until` — долгая, остаётся работать, как dev-сервер), `write` и `edit` (файл; `edit` — `find`/`replace`), `read`, `commit`, `agent: { prompt, reply }` с вложенными `steps` (они пишутся с `by: "agent"`), `browser: { url, fill, click }`. У шага `id` — постоянный: на него ссылаются уроки, переименовывать нельзя. Сессии идут цепочкой (`from`).
- **Запись** — `video/sessions/<id>.json`: события `run`, `file`, `read`, `commit`, `agent`, `browser`. Вывод очищен от цвета, временная папка заменена на `~/trainer-app`, больше ничего не правилось.
- **Что команда сделала с файлами**: у `run` есть поле `files: [{ path, blob }]` — файлы проекта, которые команда создала или изменила (`blob` — хеш нового содержимого) или удалила (`blob: null`), по пути. Рекордер сравнивает отслеживаемые и неотслеживаемые, но не игнорируемые (`.gitignore`) файлы до и после команды; до `git init` и у команд без изменений поля нет. По нему сверка записей (`sessionProblems`) знает, что после `git revert`, `git restore` или `echo … > файл` содержимое файла другое, и следующую правку (`edit`, `write`) или чтение (`read`) этого файла сверяет с хешем команды, а не со старым содержимым. Поэтому файл после таких команд править можно.
- **Браузер сессии**: один Chromium и один контекст на всю сессию (`locale: ru-RU`, пояс `Europe/Moscow`) — cookie и `localStorage` живут между шагами `browser` одной сессии (вошли на одном шаге — на следующем уже вошли), а следующая сессия начинает с чистого браузера. `urlAfter` у `browser` — адрес страницы после нажатий, если он отличается от `url`; кадр `browser` показывает в строке адреса `url`, а с реплики `at.action` — `urlAfter`.
- **Перезапись**: `node scripts/record-session.mjs` — вся цепочка (несколько минут), порт 3000 свободен, нужен доступ к реестру npm. Версии пакетов — диапазоны `^`, поэтому в другой день изменятся `package-lock.json`, хеши коммитов, число пакетов и время в выводе. После перезаписи: `npx vitest run video/sessions`, затем `npm test` целиком — уроки ссылаются на id событий и диапазоны строк, и разъехавшийся диапазон ловит тест урока.
- **Состояние после сессии и запись с середины.** Рекордер сохраняет состояние проекта после каждой сессии в `../demo-app/state/<id>.tar.gz` (архив папки проекта без `node_modules`, `.next`, `test-results`, `playwright-report`; `.git` и `.env.local` внутри). `node scripts/record-session.mjs --from <id>` записывает `<id>` и все следующие от состояния предыдущей сессии (пакеты — `npm ci` по `package-lock.json`), а записи и состояния раньше `<id>` не трогает: новая сессия дописывается, не сдвигая хеши и вывод прежних. Нет архива — «Нет состояния сессии «…»: запишите цепочку целиком» (полная запись создаёт все архивы). Команды сессии, которую пишут с середины, не должны печатать то, чего нет в состоянии до установки пакетов (`ls` с `node_modules`, `.next`). Подробности — `../demo-app/README.md`, «Запись с середины цепочки».
- **Локальная база (`db: true`).** Сессия с полем `db: true` получает свой Postgres 16 на порту 54322 со слоем Supabase (`scripts/session/supabase-local.sql`: схема `extensions` с `pgcrypto`, роли `anon` / `authenticated` / `service_role`, схема `auth` с `auth.users`, `auth.uid()` и `auth.role()`): перед первым шагом рекордер применяет слой, затем `supabase/migrations/*.sql` по имени и `supabase/seed.sql` проекта (как `supabase db reset`; их вывода в записи нет, ошибка SQL роняет запись с именем файла), а командам даёт `PGHOST`, `PGPORT`, `PGUSER`, `PGDATABASE` и `DATABASE_URL=postgresql://postgres@127.0.0.1:54322/postgres`. База живёт одну сессию и каждая следующая начинает с чистой; в конце, при ошибке шага и при выходе рекордера (в том числе по SIGHUP) она останавливается, папка удаляется; остаток после `kill -9` следующая запись с `db` убирает сама. Нужен запуск от root (иначе ошибка «Сессия с db: true: Postgres запускается от пользователя postgres, рекордер нужно запускать от root»). Это не настоящий Supabase: нет PostgREST и настоящего Auth, вход в приложении — свой маршрут с проверкой пароля через `crypt`. Когда кадр показывает базу, на доске подпись «локальная база вместо Supabase». Что поднимается и чего нет — `../demo-app/README.md`, «Локальная база вместо Supabase».
- **Адрес страницы в шаге `browser` — конечный.** Если `page.goto` по `url` приводит на другой адрес (редирект сервера: вход, перенаправление), рекордер роняет шаг: «страница открылась по адресу …, а запрошен … — укажите в шаге конечный адрес». Кадр не показывает в строке адреса того, чего у страницы не было. Переход после нажатия — другое дело, он попадает в `urlAfter`.
- **`node scripts/print-event.mjs`** — список записей; `… s02-sets` — события; `… s02-sets fix` — событие с номерами строк в тех же единицах, что и спеки кадров (для `lines`, `highlight`, `consoleLines`, `at.steps`, `ask`). Нужен Node ≥ 22.18.
- Нужной команды или правки нет в записи — добавить шаг в сессию (или новую сессию `s03-…` с `from: 's02-sets'`) и перезаписать цепочку, а не придумывать вывод. Показывать можно только то, что есть в записи; после перезаписи прогнать оба пилотных урока.

## 5. Как снять кадры и что смотреть

```sh
node scripts/lesson-stills.mjs <id> video/lessons/<id>/script.gen.json /tmp/stills/<id>
ffmpeg -pattern_type glob -i '/tmp/stills/<id>/scene-*.png' -vf "scale=640:-1,tile=3x4" /tmp/stills/<id>/sheet-%d.png
npx remotion still video/index.ts <id> out.png --frame=1234 --props='{"debugSpots":true}' --browser-executable=/opt/pw-browsers/chromium_headless_shell-1194/chrome-linux/headless_shell
```

- Первая команда собирает бандл Remotion и снимает середину каждой сцены (`scene-NN-<сцена>.png`) и каждого пояснения (`spot-NN-<сцена>.png`, с рамкой пояснения и её названием). Для набора без урока вместо `<id>` — `term-lesson` и `video/term/fixture-lesson.gen.json`. `playwright install` не запускать.
- Вторая — обзорные листы по 12 сцен; третья — один нужный кадр (конец сцены, смена сцен).
- Снимок сцены берётся на 12 кадров позже начала реплики, ближайшей к середине, — середина не показывает конец сцены: концы (кадр конца минус ~14) и границы сцен снимайте отдельно.
- Смотреть: рамки пояснений стоят на своих объектах; наезд камеры не обрезает текст (справа у строк кода, у края, у соседней панели); нет висячих слов («stat / us», «…к / живым людям»); нижняя треть окна не пустует без причины; субтитры в одну–две строки; схема прорисована, подписи не режутся рамкой фокуса; вердикт в шапке на своём месте. Пилот прошёл по три прохода «смотрю — правлю — смотрю ещё раз» на каждый ролик; без этого баги не видны ни тестам, ни линтеру.

## 6. Ловушки

1. **Длина впритык.** Потолок ролика главы — 8100 кадров, а пилот закончил на 8070 (`ch-abc`) и 8082 (`ch-01`). Новая реплика — 80–150 кадров; сокращать надо раньше, чем сцена готова. Нижняя граница — длина прежнего ролика: `lessonProblems(урок, { minFrames })`, прежнюю длину посчитать до замены (`totalFrames(catalog[id].script)` из `video/lib/timeline.ts`).
2. **Первые и последние 12 кадров сцены** — смена сцены. Пояснение не может начаться раньше 12-го кадра: реплика 0 начинается на 9-м, значит пояснение с `at: 0` нельзя — ставьте на реплику 1. Пояснение не может кончаться в последних 12: `until` равный числу реплик недопустим, без `until` окно уже кончается за 12 кадров до конца.
3. **Камера и пояснения на терминале — только без прокрутки.** Части терминала — один снимок конца сцены; цель, которую к концу уводит прокрутка, проверка отвергнет («терминал прокручивается, разделите сцену»). Сцена, где нужно смотреть на раннюю строку длинного вывода, делится на две.
4. **Шум песочницы.** Контейнер записи без доступа к `fonts.googleapis.com`: dev-сервер Next.js пишет в `server` и вывод предупреждения о Google Fonts и «Import trace». Выбирайте `lines` без них (например, из `save-ok.server` только строку 47 с запросом); `lessonProblems` на шум ругается.
5. **Латиница в репликах — только с произношением.** Любое новое латинское слово в `lines` добавляется строкой в `SAY` (`src/video/narration.ts`; длинные сочетания раньше коротких), иначе падает `narration.test.ts`. Субтитры остаются как написано.
6. **`minFrames`** — обязательный параметр теста урока; без него проверка длины не знает прежнего ролика и не поймает укорочение.
7. **`script.gen.json`** — снимок `buildLesson(урок).script` через `toMatchFileSnapshot`; сайт читает его через `script.ts`, а записи и код кадров остаются в ленивом `Video.tsx`. Правка урока (даже реплики) — прогон `npx vitest run video/lessons/<id>`; при расхождении `-u` и коммит снимка вместе с уроком. Playwright (e2e) `script.ts` не загрузит — JSON без `with { type: 'json' }` Node не принимает; e2e импортируют сам `script.gen.json`. `Video.tsx` — копия образца с пробросом пропов (`(p: { debugSpots?: boolean }) => <LessonVideo lesson={…} {...p} />`): без него `lesson-stills.mjs` снимет пояснения без рамок.
8. **Интерфейс Claude Code — только по схемам книги** `ch1_agent_session` и `dk_modes`: `Reading …`, `Edited … (+N −M)`, `Run "…"? [y / n]`, режимы Plan / Manual / Accept edits. Других английских строк интерфейса не выдумывать. По книге Manual спрашивает перед правками, а кадр рисует вопрос только перед командой, поэтому правки без вопроса показывайте в `Accept edits`. Команда не из `ask` выводится как `$ команда`. Вопрос `[y / n]` бывает только у шага-команды в записи (в пилоте — `claude-md`); у `ask-form`, `ask-fix` шагов-команд нет.
9. **Чат без ответа агента.** `chat: true` показывает запрос и блок кода, ответа нет: ответ записи — слова агента, а чат в проекте ничего не делает. Нужное место файла — `code: [от, до]`.
10. **Кадр не стоит дольше 120 кадров (4 с).** Последняя реплика длиннее ~36 знаков без нового действия даёт больше 120 кадров до конца сцены. На досках — по элементу на реплику, камера или подсветка на реплику.
11. **Один запрос — одна строка.** `\n` в `prompt` агента склеивается; длинный запрос набирается 30 знаков/с (десяток секунд на 300 знаков) — коротко.
12. **Длина дня на страницах.** Тесты `src/course/summary.test.ts`, `src/day/day.test.tsx`, `src/home/home.test.tsx` держат длину роликов дня с новыми роликами (сейчас дня 1, «8:58»); замена ролика меняет число — пересчитать.
13. **Замена старого ролика**: `catalog.ts` указывает на `./lessons/<id>/script` и `./lessons/<id>/Video`; в `src/video/registry.ts` убрать MP4 этого id; `git rm -r` старой папки `video/<id>`; поправить ссылки на неё (`grep video/<id>`); `registry.test.ts` требует `lessons/<id>/lesson.test.ts` у каждого ролика 1920. На `ch-02` и `ch-12` (день 2) стоит e2e «два старых ролика (1280 × 720) на компьютере — в один ряд» (`e2e/video.spec.ts`): при переделке любого из двух его надо перенести на другой день с двумя старыми роликами, иначе он упадёт или перестанет что-либо проверять. Снимок `src/video/narration.old-videos.spoken.txt` (озвучка старых роликов) при этом сократится — обновить `-u` осознанно.
14. **id внутри SVG — только через `svgId(id ролика, имя)`** (`video/term/ids.ts`). На странице дня смонтировано несколько роликов в одном документе, а `url(#id)` берёт первый элемент с таким id во всём документе: общий id клипа, градиента или маркера делает чужой своим (у второго ролика терялась цифра номера главы, наконечники стрелок схем брали цвет темы страницы). Схемы книги ссылаются на маркеры `bk-arrow…` страницы — `Figure` переписывает их в `term-arrow…` (`scopeMarkers`); другие ссылки `url(#…)` в схему не добавляйте без того же.
15. **Наезды камеры** хороши на схемах и досках; на окнах с длинными строками кода они режут текст справа и оставляют обрывки соседней панели. В пилоте такие наезды убраны; если нужен — смотреть снимок.

## 7. Известные недоработки набора

Не блокируют; автору следующих роликов лучше знать.

- **Пояснение у строки вывода может открыться раньше самой строки.** Команда набирается на той же реплике, строка появляется через 17–20 кадров (около 0,6 с) — видно только на паузе. Проверки «окно пояснения не раньше появления цели» нет: смотрите кадр `spot-*` и кадр на `from` пояснения. У шагов `agent` та же история: шаги ждут конца набора запроса (30 знаков/с), короткая реплика перед пояснением даёт сдвиг. Исправление для набора — проверка в `lessonProblems`.
- Проверка пояснений не учитывает сплошной фон ниже y 896 при наезде камеры (цель у нижнего края окна).
- Смена правой части шапки и заголовка не согласована на 2–4 кадра при длинных названиях; `Header` до кадра `at` прячет название.
- Ширина субтитров оценивается по среднему знаку Golos (0,54 em): у худших строк до +2 % сверх 1500 px (плашка всё равно в кадре).
- Доски: запас ширины 1,08 даёт висячие слова — смотреть переносы; `Устройство пользователя` в `abc_restaurant` касается рамки зоны (свойство схемы книги).
- Снимки: `SETTLE` (12 кадров) может поймать недорисованную линию схемы (прорисовка 19 кадров) — смотрите кадр позже. Блок книги `recap` не проверен на выход выше SAFE; ширина кикера `agenda` не проверяется; `marker-label` шкалы не имеет своего `data-part`.
- Записи: `git diff --stat` не видит новый (неотслеживаемый) файл; пустая строка в блоке диффа не принимается как контекст; `input type=submit` без текста не попадает в `buttons`; у сообщений консоли с `%c` хвост «Line: 3» обрезается.
