# Правила роликов курса

Собраны при создании 27 роликов: ограничения плана, порядок работы над роликом, набор `video/kit`, произношение и уроки ревью. Номера задач ссылаются на план `docs/superpowers/plans/2026-10-21-video-lessons.md`.

## Global Constraints

- Все пакеты Remotion строго `4.0.537`; кадр 1280×720, 30 кадров/с.
- Темп «живее»: 14 знаков/с, вступление 0,3 с, пауза между репликами 0,25 с, хвост сцены 1 с, реплика не короче 2,2 с; субтитры не быстрее 15 знаков/с.
- Длина: ролик главы 5400–8100 кадров (3–4,5 мин), ролик дня 1800–5400 кадров (1–3 мин).
- Сцен: 5–7 у ролика главы, 3–4 у ролика дня; горячих точек не меньше 2 у главы и не меньше 1 у дня, все внутри кадра.
- Текст в кадре не мельче 18 px; содержимое сцен выше y = 565 (ниже — субтитры в две строки).
- Цвета только из `course/video/theme.ts`; шрифт `theme.font`, моноширинный `theme.mono`.
- Герои: тренеры Марина (`theme.accent`) и Дима (`theme.alt`), подопечные Анна (номер 17) и Олег (номер 18), агент — робот-помощник. Анна, Ира и Костя — подопечные Марины, Олег — подопечный Димы (Марина его данных не видит — день 4); Наташа — новый тренер, Рома — её подопечный (день 15); Полина, Кирилл, Тимур, Ксения — бета-тренеры (дни 19–21); пример — приложение тренера и подопечного.
- Реплики своими словами, не пересказ книги; каждый факт, цифра и название сверяются с указанными разделами книги `vibe-coding-na-praktike-2026-10.html`.
- Голос — только синтез речи браузера на сайте; MP4 без звука, H.264, `--crf=28`, не больше 20 МБ, браузер рендера `/opt/pw-browsers/chromium_headless_shell-1194/chrome-linux/headless_shell`.
- Ролики только в курсе; книга не меняется. Дни 2–21 остаются `status: "draft"`.
- Весь текст интерфейса и роликов — по-русски.

### Задачи роликов (7–13): общий порядок

Каждый ролик `<id>` — папка `course/video/<id>/`: `script.ts` (через `buildScript`, экспорт `<camelId>Script`), `layout.ts` (координаты объектов и горячих точек), `scenes/S1….tsx`…, `Video.tsx` (`export default`, сцены в `<Sequence>` по `sceneStart`, `<Subtitles>`, проп `showHotspots`), `script.test.ts` (`scriptProblems(…, kind)` пуст). Ролик не трогает общие файлы; в каталог, `Root` и файлы дней его добавляет задача.

Шаги каждой задачи роликов:
- [ ] **Step 1:** Прочитать указанные разделы книги; написать `script.test.ts` для каждого ролика задачи.
- [ ] **Step 2:** `npx vitest run video/<id>` — FAIL.
- [ ] **Step 3:** Сценарий: по одной реплике на мысль, по одной метафоре-сцене на ролик (из задания), примеры на приложении тренера; сверить каждый факт с книгой. Сцены: каждые 3–4 с в кадре что-то меняется, текст ≥ 18 px, всё выше y = 565.
- [ ] **Step 4:** `npx vitest run video/<id>` — PASS; кадр середины каждой сцены и отладочный кадр каждой горячей точки — просмотреть, исправить наезды и обрезку, просмотреть ещё раз.
- [ ] **Step 5:** Добавить ролики в `catalog.ts` и блоки `{"type": "video", "videoId": "<id>", "title": "<название>"}` в начало `blocks` своих дней (порядок — как в таблице спецификации); `npm test` — PASS (`registry.test.ts` и `refs.test.ts` проверяют новые записи).
- [ ] **Step 6:** Коммит `video: ролики <ids>`.

## Уточнения (по итогам задач 1–6)

- Содержимое сцен держать выше y = 565 (субтитры в две строки начинаются с y ≈ 575).
- Переход и камера каждой сцены хранятся как `STAGING` в `script.ts` ролика (как в `course/video/day-08/script.ts`); рамки горячих точек считаются через `toScreen` от камеры в начале окна; в `script.test.ts` ролика — тест «окна горячих точек на неподвижных кадрах», по образцу `course/video/day-08/script.test.ts`.
- Образец устройства ролика — `course/video/day-08/` (script.ts, layout.ts, scenes/, Video.tsx, script.test.ts; пилот `pilot-rls` переделан в набор «Репозиторий»). Общие детали (`PhoneScreen`, `KeyGlyph` и др.) берутся из набора `course/video/kit/` (раздел «Набор после задачи 7k»); импортов между папками роликов нет. Добавление в набор — с тестом.
- Строки терминала, редактора и диффа — не длиннее 40 знаков; слова в чате с агентом — не длиннее ~20 знаков.
- `showHotspots` — проп компонента ролика для отладочных кадров (по умолчанию false).
- Книга: `vibe-coding-na-praktike-2026-10.html` в корне репозитория, данные — JSON после `const BOOK = `; разделы — блоки с `id` (`sa1`, `s5` …), текст читать через `python3 -I`.
- Кадры: середина каждой сцены и отладочный кадр каждой горячей точки (`--props='{"showHotspots":true}'`); команда из `course/`: `npx remotion still video/index.ts <id> <out.png> --frame=<N> --browser-executable=/opt/pw-browsers/chromium_headless_shell-1194/chrome-linux/headless_shell`. Никогда не запускать `playwright install`. После просмотра — один лист кадров (PIL, 640×360 на кадр, по 2 в ряд) во временной папке вне репозитория.


## Набор после задачи 7k

С задачи 7k общие детали роликов берутся из `course/video/kit/`, а не из папок соседних роликов (`ch-abc/scenes/parts`, `pilot-rls/scenes/*` больше не источник). Это заменяет прежние пункты «общие компоненты пилота можно импортировать из `pilot-rls`» и «тест окон горячих точек по образцу пилота».

**`kit/props.tsx` — общие детали сцен** (внешний вид не менялся при переносе):
- `Browser` — окно браузера: `{ x, y, w, h, at, url, focus?, children }`, дети в координатах окна.
- `Pill` — плашка с текстом по центру `(x, y)`: `{ x, y, w?, text, color?, fill?, size?, weight = 700, mono?, compact? }`. Без `w` ширина считается от текста; с `w` — ровно `w`. Без `compact`: рамка 3, высота `size + 20`, размер по умолчанию 22. С `compact` — плотная плашка (бывший `Tag` ch-01): рамка 2,5, высота `size + 16`, размер по умолчанию 18. Свой `size` важнее; не ставить меньше 18.
- `Mark` — галочка или крестик в кружке `{ x, y, ok, r? }`.
- `Cloud` — облако `{ x, y, w, h, children?, stroke?, fill? }`, `(x, y)` — левый верхний угол.
- `PhoneScreen` — экран телефона для `<Phone scale={PHONE_SCALE}>`: `{ tapAt, listAt, list, label = 'Мои тренировки', listColor?, children? }`; `label` — подпись кнопки (для другого ролика ставить своё), цвет подписи — `theme.white`.
- `KeyGlyph` — ключ (кольцо и бородка) `{ x, y, color, scale? }`, `(x, y)` — центр кольца.
- `Callout` — реплика героя: плашка `Pill` с текстом по центру `(x, y)` и указка с точкой к говорящему `(tx, ty)`: `{ x, y, tx, ty, text, color?, fill?, size = 20 }`. Пузыри речи берите отсюда, своей копии не заводите.
- `Slot` — пунктирное место будущего элемента: `{ x, y, w, h, r = 10, text?, color? }`, `(x, y)` — левый верхний угол, `text` — бледная подпись по центру (что сюда придёт). Пустые места под репликой рисуйте им, своей копии не заводите.
- Белый цвет — `theme.white` (`'#fff'`) из `video/theme.ts`: литерал `'#fff'` в деталях и сценах не писать.
- Размеры телефона `PHONE_SCALE = 1.5`, `PHONE_FONT = 12` лежат в `kit/screens/layout.ts` (чистый файл без React); `layout.ts` пилота их реэкспортирует, в новом ролике — так же, свои копии не заводить. `layout.ts` ролика должен импортировать только чистые файлы, иначе тяжёлый код попадёт в основной файл сайта (сценарий лёгкий и грузится сразу).
- Детали одного ролика (Waiter, Flag, Bug, KeyCap, Plane, Yoke, Pilot, You, Bubble, Ring и т. п.) остаются в `<id>/scenes/parts.tsx` ролика. Если деталь понадобилась второму ролику — переносить в `kit/props.tsx` с тестом в `kit/props.test.tsx`, а не импортировать из соседней папки.

**`kit/motion.ts` — чистые функции движения** (можно звать в циклах и условиях; хуки в `kit/hooks.ts` — тонкие обёртки над ними):
- `CLAMP` — `{ extrapolateLeft: 'clamp', extrapolateRight: 'clamp' }` для `interpolate(frame, in, out, CLAMP)`; свой `const clamp` и литерал `{ extrapolateLeft: 'clamp', … }` не писать (в пилоте и `actors/Turnstile.tsx` они уже заменены).
- `appear(frame, at, length = 12)` — плавное появление 0 → 1; `trackAt(frame, keys)` — позиция по ключам `[кадр, x, y]` с разгоном и торможением (как `useTrack`).

**`stagingProblems` в тесте ролика.** `kit/checks.ts` экспортирует `stagingProblems(script, STAGING): string[]`; своей копии проверок камеры в `script.test.ts` ролика больше нет. Подключение — одна строка:

```ts
import { scriptProblems, stagingProblems } from '../kit/checks'
import { myScript, STAGING } from './script'

it('переходы и камера на месте, окна горячих точек — на неподвижных кадрах, вне переходов, выше субтитров', () => {
  expect(stagingProblems(myScript, STAGING)).toEqual([])
})
```

`STAGING` — `Record<id сцены, { transition: 'fade' | 'slide' | 'zoom'; camera: CameraKey[] }>` (как в `day-08/script.ts`). Проверяется: у каждой сцены есть запись, переход известный, камера хоть раз двигается, ключи идут по порядку и не дальше конца сцены; каждое окно горячей точки целиком внутри одной сцены, вне первых и последних `TRANSITION_FRAMES` кадров, не короче 90 кадров, камера не движется на кадрах `[from, to)`; рамка точки (в `script.hotspots` она уже в кадре — считается через `toScreen` от камеры в начале окна) внутри кадра и выше y = 565. Каждая проблема — одна строка по-русски, с id сцены или названием точки.

## Произношение (после задачи 8)

Голос сайта читает реплики через `spokenText` из `course/src/video/narration.ts` — таблицу `SAY` «как написано → как сказать» (латиница, аббревиатуры, команды, знаки × и →). Субтитры не коверкать ради голоса: пишите как в книге. Тест `narration.test.ts` не пропускает реплику, в которой после таблицы осталась латиница. Если в ваших репликах есть латинские слова или кириллические аббревиатуры, которых нет в `SAY`, — добавьте строки в `SAY` (длинные совпадения — раньше коротких, например `Claude Code` раньше `Claude`; новая строка не должна менять реплики других роликов) и закоммитьте вместе с роликом.

## Уроки ревью (задачи 8–10) — проверьте у себя до коммита

Эти ошибки стоили раунда правок; ревьюер ищет их в первую очередь.
- **Свои слова:** ни в репликах, ни в текстах точек, ни в подписях нет цепочек из 6+ слов подряд из книги (термины и названия не в счёт). Проверяйте скриптом по тексту книги и подписям рисунков.
- **Не сильнее книги:** ни дат, ни происхождения, ни чисел, ни прогнозов, которых нет в книге; «часто быстрее» не превращать в «проще», «отличная» — в «лучшая», «именно вы» — в «только вы». Подписи не должны противоречить рисункам книги.
- **Пример верен по существу:** формулы и расчёты на экране считают правильно (объём = сумма повторов × вес по каждому подходу), код делает то, что о нём говорит реплика, псевдокод и реплика говорят об одном. Метафора тоже верна: ходы на шахматной доске, бытовые детали — без ошибок, которые заметит знаток.
- **Ролик дня согласован с курсом:** до сценария прочитайте `goal` всех предыдущих дней (`course/content/days/day-NN.json`) и реплики роликов этих дней: не «стройте» то, что приложение уже умеет (график с дня 7, уведомления с дня 11, приглашения с дня 12 и т. д.), ссылайтесь на сделанное («как в день 11»), имена и роли героев те же (Анна — подопечная Марины, Олег — Димы).
- **Пример не учит лишнему:** не подразумевайте того, что неверно (например, будто коммит сохраняет данные в базе).
- **Кадр:** окно горячей точки открывается на уже готовой схеме, а не на рисующейся — для каждой точки отрисуйте кадр `from` с `showHotspots` и убедитесь, что всё, о чём говорит текст точки, уже нарисовано полностью и до `to` не меняется (комментарий «всё на месте» у `from` проверяйте этим кадром, а не на глаз); во время реплики кадр не пустует (заранее рисуйте пунктирные места будущих элементов); ничего не останавливается на подписях и коде и не улетает к краю кадра; середина сцены — не посреди панорамы.
- **Ниже 565 — ничего, и во время движения камеры тоже:** перед коммитом отрисуйте каждый 20-й кадр ролика и проверьте, что ниже y = 565 (кроме плашки субтитров) и у краёв кадра нет обрезанного содержимого; появление мест и карточек ставьте после отъезда камеры, а не во время крупного плана.
- **Рамка точки** на сайте рисуется линией 3 px: она не должна пересекать текст и подписи — ведите её по пустому месту вокруг объекта.
- **Тексты точек:** до ~350 знаков; длинную жирную `Pill` — с явной `w`, проверить по кадру.
